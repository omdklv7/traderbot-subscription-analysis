# AS-IS Process: использование TraderBot по бессрочной лицензии

## 1. Цель процесса

Описать процесс приобретения, подключения и эксплуатации TraderBot в модели бессрочной лицензии до внедрения подписочной модели.

## 2. Границы процесса

**Начало:** пользователь принимает решение приобрести TraderBot.  
**Конец:** пользователь эксплуатирует торговую систему; при возникновении сбоев или обновлений система восстанавливается и возвращается в рабочее состояние.

## 3. Участники процесса

- Пользователь
- Информационная система TraderBot
- Техническая поддержка TraderBot
- VPS-провайдер
- Брокер / торговая платформа

## 4. Основной сценарий

1. Пользователь изучает доступные лицензии TraderBot.
2. Пользователь выбирает подходящую лицензию.
3. Пользователь оплачивает лицензию.
4. Приобретённая лицензия отображается в личном кабинете.
5. Пользователь обращается в техническую поддержку для подключения системы.
6. Сотрудник технической поддержки сообщает требования к брокерскому счёту.
7. Пользователь регистрирует и настраивает брокерский счёт при участии технической поддержки.
8. Пользователь приобретает VPS через личный кабинет TraderBot.
9. Настраивается удалённый доступ к VPS.
10. Техническая поддержка устанавливает и настраивает TraderBot на VPS.
11. Торговая система подключается к брокерскому счёту.
12. Пользователь начинает эксплуатацию системы.
13. Пользователь отслеживает работу системы через мониторинг и дашборд.

## 5. Альтернативный сценарий: технический сбой

1. Во время эксплуатации возникает технический сбой.
2. Пользователь определяет характер проблемы.
3. Если пользователь может устранить проблему самостоятельно:
   - подключается к VPS;
   - выполняет необходимые действия;
   - проверяет восстановление системы.
4. Если пользователь не может устранить проблему:
   - обращается в техническую поддержку;
   - техническая поддержка устраняет проблему;
   - работа системы восстанавливается.
5. Пользователь продолжает эксплуатацию TraderBot.

## 6. Альтернативный сценарий: обновление ПО

1. Выходит обновление программного обеспечения.
2. Определяется способ обновления.
3. Если достаточно обновить клиент, пользователь выполняет обновление.
4. Если требуется работа через удалённый доступ:
   - пользователь самостоятельно обновляет или переустанавливает необходимые файлы; либо
   - обращается в техническую поддержку.
5. После завершения обновления проверяется работоспособность системы.
6. Эксплуатация продолжается.

## Выявленные проблемы AS-IS

| ID | Проблема | Причина | Последствие |
|---|---|---|---|
| P-01 | Высокий порог входа | Бессрочная лицензия стоила от $550, дополнительно требовались депозит и VPS | Новому пользователю сложнее решиться протестировать продукт |
| P-02 | Техническая нагрузка на пользователя | Пользователь самостоятельно взаимодействует с VPS и удалённым доступом | Для использования продукта требуются дополнительные технические навыки |
| P-03 | Самостоятельное устранение части сбоев | При проблемах пользователь должен диагностировать сбой или обращаться в поддержку | Увеличивается время восстановления и зависимость от опыта пользователя |
| P-04 | Сложное обновление ПО | Некоторые обновления требуют подключения к VPS и ручной переустановки файлов | Обновление создаёт неудобство и риск неправильных действий |
| P-05 | Дополнительное управление инфраструктурой | VPS необходимо отдельно покупать и продлевать | Пользователь вынужден контролировать не только торговую систему, но и инфраструктуру |
| P-06 | Ограниченная гибкость продукта | Разные режимы и уровни риска реализованы через отдельные боты | Сложнее менять стратегию использования без смены продукта |

### Основной вывод

Ключевая проблема AS-IS заключалась не только в стоимости бессрочной лицензии, но и в распределении ответственности.

Пользователь отвечал одновременно за использование торговой системы и за значительную часть её технической эксплуатации: VPS, удалённый доступ, обновления и устранение части сбоев.

Это увеличивало порог входа и усложняло дальнейшее использование продукта.
