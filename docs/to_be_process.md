# TO-BE Process: использование TraderBot по подписочной модели

## 1. Цель процесса

Описать целевой процесс подключения и эксплуатации TraderBot по подписочной модели, в которой техническая инфраструктура и значительная часть сопровождения находятся на стороне TraderBot.

## 2. Границы процесса

**Начало:** пользователь принимает решение подключить TraderBot по подписке.  
**Конец:** пользователь продолжает эксплуатацию системы, продлевает подписку либо прекращает её использование.

## 3. Участники процесса

- Пользователь
- Информационная система TraderBot
- Техническая поддержка TraderBot
- Telegram-бот
- Брокер / торговая платформа

## 4. Основной сценарий

1. Пользователь принимает решение подключить TraderBot по подписке.
2. Пользователь регистрируется или входит в личный кабинет через e-mail или Telegram.
3. Пользователь подготавливает брокерский счёт с рекомендуемым депозитом от $500.
4. Пользователь оплачивает подписку стоимостью $50 через личный кабинет.
5. После оплаты инициируется первичная активация торговой системы.
6. Пользователь взаимодействует с технической поддержкой для подключения счёта.
7. Техническая поддержка выполняет необходимые действия для подключения TraderBot к брокерскому счёту.
8. После завершения активации пользователь получает доступ к торговой системе.
9. Пользователь начинает эксплуатацию TraderBot.
10. Пользователь контролирует работу системы через личный кабинет.
11. Пользователь может самостоятельно изменять уровень риска и режим работы системы.
12. Серверная инфраструктура, обновления и техническое обслуживание обеспечиваются командой TraderBot.

## 5. Продление подписки

1. За несколько дней до окончания оплаченного периода Telegram-бот отправляет пользователю напоминание.
2. Пользователь принимает решение о продлении подписки.
3. Если подписка оплачена вовремя, работа системы продолжается без отключения.
4. Если оплата не произведена, торговая система сразу отключается от брокерского счёта.

## 6. Повторное подключение

1. Пользователь оплачивает подписку после отключения.
2. Система автоматически восстанавливает подключение.
3. Ранее установленные настройки пользователя сохраняются.
4. Эксплуатация TraderBot продолжается.

## 7. Технический сбой

1. Во время эксплуатации возникает технический сбой.
2. Команда TraderBot выявляет и устраняет проблему со стороны серверной инфраструктуры или программного обеспечения.
3. Пользователю не требуется самостоятельно подключаться к VPS или переустанавливать необходимые файлы.
4. После восстановления система продолжает работу.

## 8. Обновление программного обеспечения

1. Выпускается новая версия программного обеспечения.
2. Команда TraderBot выполняет необходимые действия по обновлению системы.
3. При необходимости производится обновление или переустановка компонентов на серверной инфраструктуре.
4. Пользователь продолжает работу с актуальной версией TraderBot без самостоятельного обслуживания VPS.

## 9. Связь изменений TO-BE с проблемами AS-IS

| ID | Проблема AS-IS | Изменение в TO-BE | Ожидаемый эффект |
|---|---|---|---|
| P-01 | Высокий первоначальный порог входа | Подписка $50/мес вместо обязательной покупки лицензии от $550 | Снижается стоимость первого доступа к продукту |
| P-02 | Высокая техническая нагрузка | Инфраструктура обслуживается TraderBot | Пользователю не требуется администрировать VPS |
| P-03 | Самостоятельное устранение части сбоев | Технические проблемы устраняет команда TraderBot | Снижается зависимость от технических навыков пользователя |
| P-04 | Сложное обновление ПО | Обновления выполняются централизованно | Пользователь не работает с файлами и VPS вручную |
| P-05 | Необходимость покупать и продлевать VPS | Серверная инфраструктура входит в подписочную модель | Устраняется отдельный процесс управления VPS |
| P-06 | Ограниченная гибкость отдельных ботов | Единая система с изменяемым уровнем риска и режимом торговли | Повышается гибкость управления продуктом |

## 10. Основной эффект TO-BE

В целевой модели значительная часть технической ответственности переносится с пользователя на TraderBot.

Пользователь концентрируется на управлении торговой системой и её параметрами, тогда как серверная инфраструктура, обновления и устранение технических сбоев выполняются командой TraderBot.

Одновременно подписочная модель снижает первоначальную стоимость доступа к продукту с $550 за бессрочную лицензию до $50 за первый месяц использования.
